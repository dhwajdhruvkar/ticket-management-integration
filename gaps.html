The gaps — and their solutions

Each card pairs what's missing with how to close it. Priorities: P0 = blocker, P3 = nice-to-have.

🗄️

Persistence & backend

P0 · Blocker
What's missing
  • All data lives in localStorage via src/lib/db.ts
  • One browser = one workspace; teams can't share tickets
  • No backups, no durability, no cross-device sync
Solution for Netlink
  • Move storage to Postgres on Azure (matches Netlink cloud)
  • Keep the db.ts contract — swap implementation, UI untouched
  • Prisma/Drizzle schema for tickets, articles, audit, users, tenants
  • Nightly backups + PITR in US region for client data residency
🔐

Auth, users & roles

P0 · Blocker
What's missing
  • Agents are hardcoded strings ("agent.demo")
  • No login, no sessions, no RBAC, no multi-tenancy
  • No org / brand / department isolation per Netlink client
Solution for Netlink
  • Azure AD SSO for staff + SCIM provisioning
  • Roles: super-admin · tenant-admin · agent · requester
  • Tenant per client (Gold/Silver/Bronze) + one netlink-internal tenant
📬

Omnichannel ingest

P0 · Blocker
What's missing
  • Only webhook ingest — no email, chat, voice, social, WhatsApp
  • No live chat widget for end users
  • No in-app messenger (Intercom-style)
Solution for Netlink
  • Outlook / M365 inbound via Graph API for staff & clients
  • Microsoft Teams bot — primary channel for Netlink staff
  • Chat widget for client portals; Twilio for voice/SMS later
⏱️

SLAs, routing & queues

P1 · Table-stakes
What's missing
  • No first-response / resolution-time targets or breach alerts
  • No round-robin, skill-based, or load-based assignment
  • No queues per Netlink pod (US-IT, India-IT, HR, client pods)
Solution for Netlink
  • SLA engine with per-tier targets (Gold 15m / Silver 1h / Bronze 4h)
  • Follow-the-sun routing — US business hours → India pod after EOD
  • Skill tags (network, AD, M365, Azure) drive auto-assignment
🎫

Ticket fundamentals

P1 · Table-stakes
What's missing
  • No merge / split / link / parent-child tickets
  • No CC, internal notes vs public replies, macros, custom fields
  • Priority enum exists but nothing acts on it
Solution for Netlink
  • Add TicketComment with visibility: public|internal
  • Macro library seeded from Netlink's existing canned responses
  • Custom fields per tenant (e.g. client cost code, project ID)
🌐

Customer-facing portal

P1 · Table-stakes
What's missing
  • Requesters can't log in to view their tickets
  • KB is internal-only — no branded help center per client
  • No status emails, no CSAT / NPS surveys
Solution for Netlink
  • Multi-brand portals: support.netlink.com + support.netlink.com/{client}
  • Public KB with each client's own articles & logo
  • Magic-link auth for client end-users; M365 SSO for staff
🤝

Real-time collaboration

P1 · Table-stakes
What's missing
  • No live updates — agents see stale ticket state
  • No @mentions, presence, or collision detection
  • No unified inbox across channels
Solution for Netlink
  • Supabase Realtime / SSE so US & India pods see live state
  • @mentions fan out to Microsoft Teams channels
  • "Currently viewing" pill prevents double-replies across timezones
⚙️

Automation builder

P2 · Differentiator
What's missing
  • No triggers / business rules beyond the AI resolver
  • No scheduled jobs (auto-close stale, follow-ups)
  • No approval flows or workflow designer
Solution for Netlink
  • Rule engine: when X · if Y · then Z stored as JSON
  • Pre-built packs: onboarding flow, access request approval, incident → Jira
  • Dry-run preview before turning a rule on against live tickets
📊

Reporting & analytics

P2 · Differentiator
What's missing
  • Only basic deflection / containment / confidence avg
  • No agent leaderboards, CSAT trends, channel breakdowns
  • No client-billable reports for Netlink's MSP engagements
Solution for Netlink
  • Per-tenant dashboards: tickets, SLA, CSAT, deflection
  • Client-ready PDF reports auto-mailed monthly
  • Engineer time-on-ticket → export to billing / project accounting
🧠

Deeper AI features

P2 · Differentiator
What's missing
  • No sentiment, auto-tagging, language detection, summarization
  • No next-best-action coach for agents
  • No bilingual support (English + Hindi) for Netlink's mixed teams
Solution for Netlink
  • Reuse /api/generate for classify · summarize · translate
  • Auto-tagging from Netlink's ITIL taxonomy (Incident / Request / Problem / Change)
  • Hindi ↔ English auto-translate so US clients and India pods stay aligned
🔌

Integrations for Netlink's stack

P2 · Differentiator
What's missing
  • Webhooks ingest only — no push-back to existing tools
  • No Microsoft Teams, Confluence, Jira SM, ServiceNow bridges
  • No public REST API or outbound webhooks
Solution for Netlink
  • Confluence importer bootstraps the KB from existing pages
  • Jira SM + ServiceNow 2-way sync (clients keep their system of record)
  • Teams app: ticket creation, notifications, agent actions inside Teams
  • Versioned REST API under /api/v1 + outbound webhook hub
🛡️

Enterprise & ops

P3 · Scale
What's missing
  • No SAML/SCIM, 2FA, IP allow-list, data residency
  • No tests, error monitoring, logging, rate-limiting
  • No CI/CD, no mobile app, no a11y baseline
Solution for Netlink
  • Azure AD SAML/SCIM (already Netlink's IdP); US data residency by default
  • Sentry + structured logs + Upstash rate-limit on public routes
  • Vitest + Playwright + GitHub Actions; PWA wrap for on-call mobile use

Why Netlink should build this — not buy Zendesk

We won't out-feature Zendesk on every checkbox. We win by owning auditable, multi-tenant, AI-first support that fits Netlink's MSP model.

The wedge: auditable AI helpdesk built around Netlink's reality

Internal IT + HR + multi-tenant client desks, on Netlink's existing Azure / M365 stack.

SOC 2 / ISO evidence

SHA-256 hash-chained audit log — directly maps to common access & change controls.

Explainable AI

Confidence, citations, reasoning are visible — defensible to enterprise clients & auditors.

Private / BYO LLM

In-browser MiniLM today; on-prem or VPC-hosted model for sensitive client tenants tomorrow.

True multi-tenant

One install, isolated KB & SLAs per Netlink client — built for MSP economics, not retrofitted.

Fits Netlink's stack

Azure AD SSO, Teams bot, Confluence import, Jira/SNOW sync — no rip-and-replace.

Owns the IP

The recommendation

Ship P0 + P1 (≈10 weeks) to make it credible inside Netlink IT & HR. Ship P2 (next 6–8 weeks) — Teams app, Jira/SNOW sync, per-tenant dashboards — and Netlink can offer this to managed-services clients as a value-add or a standalone product. Depth on the AI / audit / multi-tenant axes beats checkbox breadth.
