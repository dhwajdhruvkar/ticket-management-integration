Our AI Helpdesk vs. the Traditional ITSM Build

The previous ITSM design is a classic, human-driven ticket tracker — agents resolve everything and AI is a "someday" phase. This build inverts that: the AI resolves first, humans handle the exceptions, and every decision is recorded in a tamper-proof audit chain. Below: a side-by-side of what each does, what we already ship, and exactly how we close the remaining gaps.

How we close the gaps

What the traditional ITSM design has that we don't yet — paired with the concrete fix. P0 = blocker · P1 = table-stakes · P2 = differentiator.

🗄️

Real backend & persistence

P0

Today: all data lives in localStorage — one browser = one workspace, no sharing or durability.

The fix Swap db.ts for Postgres on Azure. The storage contract is the single chokepoint, so the engine & UI stay untouched. Add nightly backups + US data residency.
🔐

Authentication & RBAC

P0

Today: identity is a mock persona switcher — no login, sessions, or access control.

The fix Azure AD SSO + SCIM provisioning (Netlink's existing IdP). Roles: super-admin · tenant-admin · agent · requester, enforced server-side.
🔁

Problem Management

P1

Today: no root-cause / known-error tracking when the same incident repeats.

The fix Add a Problem entity linking related incidents → root cause → known-error → workaround, and surface "linked problem" on the ticket.
📝

Change Management + approvals

P1

Today: no change records and no approval workflow (standard / normal / emergency).

The fix Change request type with an approval state machine (request → assess → approve → implement → review) and manager approver role.
📬

Omnichannel intake

P1

Today: tickets are created in-app only — no email or chat capture.

The fix Outlook / M365 inbound via Graph API and a Microsoft Teams bot as the primary staff channel; feed both into the same resolver.
🖥️

Asset & CMDB

P2

Today: no hardware / software / license inventory or configuration-item map.

The fix Asset & CI entities with relationships (App → Server → Network); link affected CIs to incidents for impact analysis.
⚙️

Automation & rules engine

P2

Today: no business rules beyond the AI resolver — no auto-assign, auto-close, or scheduled jobs.

The fix "When X · if Y · then Z" rules stored as JSON, plus scheduled jobs (auto-close stale, follow-ups) with a dry-run preview.
📊

Reporting depth

P2

Today: solid in-app KPIs, but no exportable or per-tenant client reports.

The fix Per-tenant dashboards + auto-mailed monthly PDF reports; engineer time-on-ticket exported to billing for MSP clients.

The bottom line for Netlink

Keep the ITIL backbone the old design got right — lifecycle, SLA, assignment, KB, roles — but lead with what this build adds: AI-first deflection with explainable, cryptographically tamper-proof decisions. Ship the two P0 items (backend + auth) to make it production-real, layer Problem / Change / omnichannel for parity, and the AI + audit moat is what wins enterprise and MSP deals that a traditional tracker can't.
